Message Checker

● Runs in your browser

Original teaching format: a JSON array of objects with id (unique sent label), at (shared-clock elapsed milliseconds), and text (payload). Up to 200 events per log. Keep each log in chronological order; ties use array order.

Example event: {"id":"A","at":30,"text":"Hello"}. Text comparisons are exact, including spaces and Unicode. These are synthetic examples, not historical traces.

Inputs stay in this tab. No account, tracking or automatic saving. After loading, the utility and downloads work offline; reloading requires a connection or a local server.

Read RFC 4 ↗Official metadata ↗Errata ↗

RFC 4 asks collaborators to agree on test messages and checks, then examine message integrity, delivery sequence and delay. It also calls for testing abnormal conditions, outages and recovery.

This original educational tool turns those test objectives into a small trace comparison. The mixed-fault example lets learners distinguish several symptoms without pretending the log alone can identify a cause.

Model & limitations. RFC 4 leaves message formats and checking procedures to agreement. Our JSON schema, shared-clock timing and exact text comparison are modern assumptions. This is not an IMP emulator, wire-protocol test, checksum or live network measurement. Missing means absent in this finite trace, not proven lost; a gap does not prove an outage. Delay is one-way in the chosen clock, not RTT. Counts may overlap when an event has several issues.

Try it with someone

A two-minute experiment

Load Mixed faults. Identify the missing ID, the changed payload and the duplicate receipt. Move A before C while keeping timestamps chronological. Which delivery-order warning disappears, and which problems remain?

Expected observation

The initial mixed trace has missing B, changed A, a duplicate A, unexpected X and one order break. Reordering first arrivals removes the order break, but does not repair the other evidence.
